# teaching-material-writer

帮助本科高校讲师编写教学材料的 AI 技能：课程大纲、讲义、课件、概念讲法设计、作业与试题。方法论蒸馏自 JetBrains「Kotlin for Education」全学期教学资源包（联合康斯坦茨大学等高校打磨，13 讲、625 页幻灯片、518 页讲师备注，发布前经两所大学实跑验证），逐页分析后提炼，全部证据可溯源。

## 示例

下面是一个真实使用示例：以 [Cordis](https://github.com/cordiverse/cordis) 开源框架（DeepSeek Harness 底层框架，最初诞生于机器人框架 Koishi.js）为课件对象、DeepSeek V4 Flash 为模型，提示词如下：

> 我是高校计算机专业教师，请帮我为 Cordis 框架编写教学课件。需要包含 Marp markdown slides 和 plain markdown docs，课程面向低年级前端/Node.js 实践课，计划教学时长 8+ 学时（一学期课程）

~~~Markdown
# Why：为什么值得学（1/2）

没有插件机制的世界：

```js
// 你 6 个月后写出来的东西
index.js   // 2000 行，3 个人一起维护
```

- 加一个功能 = 改一段旧的代码
- 删一个功能 = 不知道哪里还引用它
- 一个人改错 = 全体遭殃

# Why：为什么值得学（2/2）

有插件机制的世界：

```
main.ts
└── plugins/
    ├── 早八提醒.ts    ← 我加我的
    ├── 复读机.ts      ← 你加你的

- 加功能 = 加一个新文件，不碰别人的
- 删功能 = 拔掉一个插件，副作用自动清理
- 分工 = 每人维护自己的插件
~~~

~~~Markdown
# 第 1 章 导论：Cordis 是什么

## 本章目标

- 理解 Cordis 的定位：一个"元框架"（Meta-Framework）
- 理解"时空可组合性"（Spatiotemporal Composability）的含义
- 了解 Cordis 的核心概念与生态
- 了解 Cordis 与普通框架的区别

---

## 1.1 我们为什么需要框架

软件开发中反复出现的问题：

- 模块之间如何**依赖**？谁先启动？
- 模块如何**通信**？事件还是直接调用？
- 模块如何**卸载 / 重载**？资源如何释放？

传统做法（手动编排）：
```ts
const db = createDatabase()        // 手动创建
const server = createServer(db)    // 手动注入
server.start()                     // 手动启动
```

问题：模块一多，启动顺序与资源释放全靠人肉维护。

---

## 1.2 什么是元框架

> A **Meta-Framework** of Spatiotemporal Composability.

- **框架**：提供固定的骨架，你在它的约束下写代码
- **元框架**：框架之上的框架 —— 定义"如何组织其他框架 / 模块"

Cordis 不直接解决"业务问题"（如数据库、HTTP、聊天机器人），
而是解决"**模块如何组合**"这个通用问题。

---

## 1.3 两个关键词：时间 × 空间

**时空可组合性（Spatiotemporal Composability）**

| 维度 | 问题 | Cordis 的答案 |
| --- | --- | --- |
| 空间（Spatial） | 谁依赖谁？ | 服务容器 + 依赖注入（`inject`） |
| 时间（Temporal） | 何时启动 / 卸载？ | 插件生命周期 + `effect` 自动回收 |

- **空间**：通过 `ctx.xxx` 获取服务，而不是 `import`
- **时间**：声明副作用后，Cordis 保证在合适时机自动销毁
~~~

两个版本的差异不在文笔，而在认知秩序。未用 Skill 的版本第一屏就是术语清单（元框架、时空可组合性），学生尚未疼痛先吃解药；用了 Skill 的版本前四页只有场景、反例与对比，「时空可组合性」被压到期待建立之后才出场。同时，后者的每一页都带 HTML 注释形态的讲师备注——提问脚本与期望答案、时间分配、「第 5 讲展开」的延期锚点：页面给学生，剧本给讲师。

## 核心方法

元信念：学生先「想要」，再「知道」——术语是解药的名字，解药登场之前，病必须先被看见。由此推导出七个心智模型：

- **张力先于术语**：概念名词永远最后出场，前面是完整的痛点演进弧
- **一例贯穿**：一门课只用一个主例子，复杂度全部加在机制层
- **双层分工**：幻灯片是学生带走的锚点，讲师备注是课堂剧本，任何信息只出现在一层
- **重复即设计**：讲过程必用序列，同一面板跨多页、每页只变一处
- **差异教学**：新概念的第一句话永远是「它像你已会的 X，区别只有一点」
- **诚实的近似**：每次简化声明边界，每次延期锚定到「第 X 讲」
- **结构契约**：先声明可裁剪的课程骨架，评估结构与教学块同构

这些直觉多数有教育学理论对应（Productive Failure、认知负荷理论等），锚点强弱在 SKILL.md 中分级标注，未过度声称。

## 怎么用

将 teaching-material-writer 目录复制到项目的 .agents/skills/ 下，或者使用 Vercel Skills CLI 安装：

```shell
npx skills add composable-tu/kotlin-for-edu-sinicization
```

之后直接提出教学请求即可自动激活，例如：

- 帮我写一节《数据库索引》的课件，45 分钟课
- 学生总说听不懂递归，帮我设计讲法
- 这是我们学院的《数据结构》大纲，帮我改进
- 帮我出一份这一讲的测验，附讲评

技能内部按「全新创作 / 概念讲解 / 改造现有材料 / 评估设计」自动路由，并设有跨学科、补救教学、课时冲突等异常路径。产出课件时会同时给出页面内容和讲师备注两层，缺一层的交付视为不完整。

## 边界

语料来自单一编程学科，向其他学科推广属迁移推断（技能会自动替换载体）；不覆盖视频课拍摄、实验课设计与高校制度性事务（教材立项、课程思政等），涉及时会明示超出范围。
