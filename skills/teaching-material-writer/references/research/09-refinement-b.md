## 一、四项评审逐项结论

### 1. 激活触发条件 —— OK（有一个可顺手补的小缺口）

- **长度**：description 实测 249 字符（含换行），低于 skill-loader 的 300 字上限。✅
- **正向触发词覆盖**：良好。「编写/改进教材、讲义、课件、教案、课程大纲、讲稿、出题、设计作业」覆盖了主要交付物名词，且配了三个真实口语问句（「这个概念怎么讲学生才懂」「帮我备这节课」「这门课怎么排」），命中讲师的自然说话方式。✅
- **防误触发**：存在——「一般性的写作润色、非教学场景不触发」。✅
- 小缺口（不阻塞）：缺「出卷/试卷/习题/期末考核」「做个课件」等高频口语变体；「备课」只以「帮我备这节课」的形式出现。语义相近，误漏概率低，可在改动1落地时顺手在 description 的「出题」处扩为「出题、出卷」。

### 2. 任务路由 —— 问题（本次评审最关键发现）

- 现有三类：全新创作 / 概念讲解设计 / 改造现有材料；每类的第一步都明确（2-A 先出结构契约给用户确认；2-B 先问「这个概念解决什么问题」；2-C 先诊断不重写）。✅
- **问题①：评估设计无路由。** description 明确承诺「出题、设计作业」「作业与试题设计」，激活后分类表里却没有对应类型。用户说「帮我出一份期中试卷」「出几道练习题」时，AI 只能硬套 Step 2-A，而 2-A 的第一步「先出结构契约（主题列表+依赖链+三层划分）」明显不对路。相关方法其实都在（模型7的评估金字塔、决策启发式4的「干扰项=典型误解」、作业选材三准则、成果映射），只是没有入口把它们串起来。
- **问题②（次要）：本土化改编无路由。** `05-translation-insights.md` 专门调研了译者注类型学、术语三档制、外来资源检查清单，但分类表没有「翻译/改编外来资源」类型，此类任务同样会被 description 的「改进/改编」措辞吸引进来后无路可走。

### 3. 失败预防 —— 问题

- **「帮我写课件」零背景场景**：现有指导是「用户没说就先问，**或**按默认值推进并声明假设」——一个「或」字把决策权交给临场发挥，不同会话行为会漂移：可能连环追问惹恼用户，也可能闷头按假设写完一整门课。缺一条可判定的规则（何时必须问、何时可默认推进）。
- **必问清单本身有漏洞**：三个开场必问只列了 受众/载体/定位，唯独没有最根本的**主题（哪门课、哪个学科）**。用户只丢「帮我写课件」时，连讲什么都不知道，「按默认值推进」是危险的——AI 会自己发明一门课。
- **非编程学科场景**：处理正确。诚实边界写明「向人文社科、数学、实验学科推广时，保持模式、替换载体，标注『跨学科迁移属推断』」——这是「继续服务+降级声明」而非拒绝服务，不会触发过度边界声明。✅

## 二、具体文本改动建议

### 改动1（最关键）：路由表补「评估设计」类型 + 新增 Step 2-D 流程

**位置A（替换）**：SKILL.md 第186-190行的分类表，替换为新表（新增第四行）。

```markdown
| 类型 | 特征 | 行动 |
|------|------|------|
| **全新创作** | 从零写大纲/一节课/一门课 | → Step 2-A |
| **概念讲解设计** | 「X怎么讲学生才懂」 | → Step 2-B |
| **改造现有材料** | 已有课件/讲义要改进 | → Step 2-C |
| **评估设计** | 出题、出卷、作业/测验/项目设计 | → Step 2-D |
```

**位置B（插入）**：第212行（Step 2-C 第3条）之后、第214行「⚠️ 无论哪种流程」段之前，插入：

```markdown
### Step 2-D · 评估设计流程

1. 先定位评估层级（对应结构契约的评估金字塔）：逐主题测验（细）→阶段实践测试（中）→阶段项目（综合）→期末（整条主线）——层级决定题型形态与难度分布
2. 声明考核边界：作业/测验区间**永不跨教学块**，只考已交付内容；期末只考不可裁剪的主线
3. 概念题按 Peer Instruction 改造：每个干扰项必须对应一条**学生真实典型误解**（写不出对应误解的干扰项删掉）；可配「预测-停顿-揭晓」用于课堂概念投票
4. 实践/项目题选材按贯穿例子三准则（需求零负担/概念全覆盖/动机呼应），优先复用课程贯穿例子
5. 每道题回链学习成果：标注它考察哪条「完成X后，学生将能够……」；映射不到任何成果的题删除
```

**理由**：description 承诺了出题/作业设计却没有路由入口，导致激活后 AI 只能硬套「全新创作」流程。改动1把已有但散落的方法（评估金字塔、干扰项=典型误解、三准则、成果映射）收拢成一条有明确第一步的流程。

### 改动2：把「先问还是默认推进」变成可判定规则，并补上「主题」

**位置（替换）**：SKILL.md 第192行整段，替换为：

```markdown
**三个开场必问：主题**（哪门课、哪一节？学科是什么？）·**受众**（几年级？先修了什么？）·**载体**（课件/讲义/教材/大纲？课时多少？定位是主线还是可裁剪外缘？）。

**何时必须先问、何时按默认推进——按缺失程度判定**：
- **主题或受众完全未知**（如用户只说「帮我写课件」）→ 必须先问：一次性问完（≤3个问题，每问附2-3个候选选项降低回答成本），得到回答前不产出正文
- **主题、受众已知，只缺载体细节/定位** → 按默认值推进，但在产出开头用一行显式声明假设（例：「假设：大二、已修X、45分钟课件」），用户可一句话纠正
```

**理由**：原文「先问，或按默认值推进并声明假设」是二选一的无判定规则，不同会话行为漂移；且必问清单漏了最根本的「主题」，在连讲什么都不知道时按默认推进会凭空发明一门课。改动2给出确定性判定，并把「主题」补进必问清单。

### 改动3：载体规范补「作业/试题」小节（兑现 description 的承诺）

**位置（插入）**：SKILL.md 第254行（「### 大纲」小节末条）之后、第256行「---」分隔线之前，插入：

```markdown
### 作业/试题

- 每题标注挂点（「配合第X讲」/「完成第X阶段后」）与所考察的学习成果条目
- 概念题：题干给场景不给定义；每个干扰项对应一条典型误解，讲评时逐项点名
- 编程/实践题：错误版与正确版同一任务、可并排讲评；评分点用「学生将能够……」的行为动词描述层级
- 试卷结构镜像教学块结构（评估同构）；覆盖比例≈各块课时占比，可裁剪外缘内容不进期末
- 讲评材料与试题同步产出：每题配一句「这题在惩罚哪个没建立的模型」
```

**理由**：Step 3 指示「按下面的载体规范输出」，但规范只覆盖 课件/讲义教材/讲师备注/大纲 四种载体；评估设计任务（改动1新增的 2-D）产出时会落入无规范可依的空档。
